## Что из этого следует и ещё не сделано

- Кнопки в C: владелец раньше говорил, что капс выглядит «слишком по-киберпанковски», и хотел увидеть обычный регистр. Вместе с четырьмя новыми вариантами показать кнопку C в двух видах — капсом и обычным регистром (срезанный угол и кромка остаются).
- Inter выбран ради одинакового вида на всех ОС, а не из-за отличий на Mac (на Mac разницы с системным шрифтом владелец не увидел).
- Четыре пункта «новый вариант» (поле, hover основной кнопки, выключенное состояние, фокус) нужно нарисовать и показать перед тем, как закладывать в пакет.
- Слово бренда на JetBrains Mono: перевести в контуры (как сделано для Menlo в `tools/extract-glyphs.py`), подобрать обводку, выпустить логотип в SVG. Нынешние картинки в `inputs/` набраны Menlo.
- Inter и JetBrains Mono придётся вкладывать в приложения файлами (сейчас в них системный шрифт); метрики Inter чуть отличаются от SF Pro и Segoe UI — после замены проверить обрезку строк.
- В обоих приложениях есть цвета мимо токенов (`amber`, `emerald`, `green`, `red`) — их нужно свести к `warning`, `success`, `error`.

## Доводка направления C (2026-11-23, вторая серия)

| Вопрос | Решение |
| --- | --- |
| Подписи на кнопках | Обычный регистр, Inter (пластина со срезом и кромкой остаётся) |
| Наведение на основную кнопку | Приподнимается: сдвиг на 1px вверх, кромка 3px → 5px, цвет не меняется |
| Выключенное состояние | Штриховка под 135°, текст `text-dim` |
| Фокус с клавиатуры | Жёлтое кольцо 2px, отступ 3px, на `:focus-visible` |
| Поле ввода | Со срезанным углом: углы 2px, срез 8px справа снизу; фокус — жёлтая рамка и нижняя полоса |
| Углы панелей, меню, вторичных кнопок | По шкале Vimperium: 6px кнопки, 8px панели и меню. Срезы только у жёлтых деталей и поля |
| Обводка слова бренда | Средняя, 5% кегля, разрядка 2% |

Этим снят конфликт «шкала скруглений из Vimperium» против острых углов C: шкала Vimperium действует
для всего, кроме жёлтых деталей (основная и опасная кнопка, плашка, метка) и поля ввода — у них 2px и срез.
Радиус 12px для полей из шкалы Vimperium не используется.

## Что теперь источник истины

- `tokens/tokens.json` — токены (правится только он); `npm run tokens` собирает `tokens/tokens.css` и `tokens/tailwind-theme.css`.

- `components/components.css` — эталон компонентов на токенах (образец для общего пакета).

| Значки внутри адресной строки (замок, тёмные страницы) | Без своей плитки, по той же логике, что кнопки шапки: только значок, пластина под курсором (`IconButton bare`) | Плитка `surface-3` под значком (было) |
| Метка режима | Полные слова COMMAND и INSERT, не CMD и INS | — |

Поля в настройках и диалогах остаются с обычной рамкой бренда: строка без рамки — только для шапки, рядом с кнопками без рамок.

## Светлая тема заново (2026-11-25)

- Прежняя светлая тема (чёрная пластина, жёлтый текст на ней, фон «бумага») владельцу не нравится: акцент чёрный, режим ввода — «чёрное становится чернее», несимметрично тёмной.
- **Светлая тема по умолчанию — белая (вариант F на `light3.html`):** фон чистый белый, панели нейтрально-серые; пластина жёлтая с чёрным текстом, как в тёмной теме, **без чёрного контура**.
- Остальные светлые фоны остаются на выбор: бумага, холодная сталь, камень.
- Отвергнуто: A (жёлтая пластина с чёрным контуром — контур у меток и полос смотрится плохо), C «маркер» (слишком много чёрного и жёлтого), B «янтарь», D «тёмный хром».
- Не решено: цвет кромки пластины, черта режима ввода и кольцо фокуса на белом (янтарные из тёмной темы на белом кажутся коричневыми) — варианты на `light4.html`. В токены белая тема вносится после этого выбора.
- **Решено (владелец, `light4.html`):** кромка пластины в светлой теме — жёлтая потемнее (`#e5c440`; янтарная на белом читается коричневой); режим ввода — поле адреса целиком жёлтое, как пластина, без тонкой черты; кольцо фокуса — чёрное.
- Правило из этого: на светлом жёлтый показывается только площадью. Для тонкого на фоне заведён токен `accent` (тёмная — жёлтый, светлая — чёрный).
- В токенах: `light` — белая тема; фоны на выбор — `light-paper`, `light-soft`, `light-steel`, `light-stone`. Пакет `@bedware/ui` 0.4.0.
- **Выбранная строка в светлой теме** (владелец, 2026-11-25): светло-жёлтая заливка (токен `selected-bg`) с чёрной кромкой слева — как в варианте «Маркер»; чёрная кромка на сером фоне ему не понравилась. Жёлтая плашка-метка выбранной строки — с чёрным контуром. В тёмной теме без изменений.

## Заголовки страниц настроек (2026-11-25)

- Владелец: в Settings обоих приложений заголовки разнобойные — где-то жирные, где-то с иконкой, разных размеров, у части страниц заголовка нет. Нужна одна система, отражённая в дизайн-системе.
- **Четыре уровня, других нет:** страница — `PageHeader` (пластина с номером, название как у пункта навигации, описание страницы); раздел — `SectionTitle`; подраздел — `SectionTitle level={2}`; название настройки — `PanelRow title`. Значков в заголовках нет; размер, толщину и регистр задаёт компонент, не страница.
- Каждая страница настроек в Runwa и Vimperium начинается с `PageHeader`; описание страницы, если оно было отдельным абзацем, переезжает в него.
