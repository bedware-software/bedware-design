# bedware-design

Бренд и дизайн-система организации **bedware software** (продукты Runwa, Vimperium, приватный Nota). С пользователем общаться по-русски.

## Главные правила

1. **Слово «bedware» всегда строчными** — в интерфейсе, заголовках, документах, названиях, в начале предложения тоже. Никогда «Bedware».
2. **Источник истины — этот репозиторий. Дизайн-система в Claude — его копия.** Любая правка цвета, шрифта, размера, компонента, логотипа или текста бренд-бука делается в файлах-источниках здесь, затем пересборка, затем публикация. Дизайн-систему в Claude вручную не правят и не правят «в обход» — ни на её странице, ни прямой записью файлов в артефакт.
   - Если пользователь просит «поменяй в дизайн-системе» — это значит: поменяй в источнике здесь и опубликуй заново.
   - Если на странице дизайн-системы обнаружились правки, которых нет в репозитории, — не затирать молча: показать пользователю разницу и спросить, переносить ли её в код.
3. **Сгенерированные файлы руками не править** (список ниже) — только их источники.
4. **Приложения:** `/Users/bedware/Development/Fun/runwa` и `/Users/bedware/Development/Fun/vimperium`. Этап миграции начат владельцем 2026-11-23. Runwa: работать прямо в `main` (так решил владелец), коммиты локальные, пуш — только по его команде. Vimperium: тоже прямо в `main` (владелец 2026-11-23: смотрит результат в установленном приложении); готовое выпускать навыком `prod-iter` (`scripts/prod-iter.sh`: сборка, переустановка, перезапуск, пуш). Ветка `bedware-design` слита.
5. **Этот репозиторий — открытый на GitHub:** `bedware-software/bedware-design` (решение владельца от 2026-11-23, чтобы приложения могли подключать пакет). Пушить только `main`, ветку `ui-dist` и теги `ui-v*`; всё в репозитории видно всем — секреты и личное сюда не класть. В `runwa` и `vimperium` без просьбы владельца не пушить.
6. `inputs/` — исходники бренда от пользователя: не менять и не удалять.
7. Решения пользователя записаны в `DECISIONS.md`. Не пересматривать их без его просьбы; новые решения дописывать туда же.
8. Пользователь выбирает глазами: перед тем как закладывать что-то новое (тему, компонент, состояние), показать 2–3 варианта на локальной странице и дать выбрать.

## Темы и токены

- Две темы: `dark` (основная, по умолчанию) и `light`. Включается атрибутом `data-theme` на любом предке; `data-theme="system"` берёт тему ОС.
- Компоненты используют только смысловые токены (`plate`, `on-plate`, `plate-edge`, `focus`, `link`, `surface-*`, `text-*`…). `yellow` и `peach` напрямую в компонентах не писать: в светлой теме пластина чёрная, а жёлтый — текст на ней.
- Новый цвет добавляется в `tokens/tokens.json` сразу для обеих тем.
- Ступени яркости: `dark-soft` и `light-soft` (в `tokens.json` это темы с полем `base`, в них записаны только отличия от своей темы). Включаются атрибутом `data-theme-variant` на том же элементе, что и `data-theme`; при `data-theme="system"` приложение само ставит ступень той темы, что сейчас в ОС.

## Порядок любой правки

1. Изменить источник (таблица выше).
2. Пересобрать: `npm run tokens`, при необходимости `npm run logo`, затем `npm run ui` (пакет и витрина; `npm run ui:check` — проверка типов), затем `npm run design-system`.
3. Проверить на локальной странице: `npm run serve` → http://localhost:4173/ui.html (все компоненты пакета во всех состояниях, обе темы) и http://localhost:4173/system.html (итог: логотип, компоненты, токены).
4. Закоммитить и отправить `main` на GitHub. Если правка должна дойти до приложений — выпустить пакет (раздел о пакете ниже).
5. Опубликовать в дизайн-систему (раздел ниже).

## Пакет компонентов `@bedware/ui`

- Папка `packages/ui`, npm-workspace этого репозитория. TypeScript, React 19 — peer-зависимость, других зависимостей нет (значки передаёт потребитель).
- Компоненты: `Button`, `InputField` / `Field`, `Select`, `Segmented`, `Switch`, `Panel*`, `Menu*`, `ConfirmDialog`, `ResultRow` / `CommandRow` / `RowKey`, `Kbd` / `Hint` / `HintBar`, `Badge`, `Tag`.
- Компонент — это разметка и поведение; внешний вид целиком в `components/components.css`. Новый вид или состояние: сначала класс в `components/components.css`, потом свойство компонента, потом образец в `demo/stories.tsx`.
- Подключение в приложении: `import '@bedware/ui/tokens.css'`, `'@bedware/ui/styles.css'`, при необходимости `'@bedware/ui/fonts.css'`; тема — `data-theme` на предке.
- Поведение и размеры взяты из приложений (`VimSelect`, `Segmented`, `Switch`, `InputField`, `ConfirmDialog`, `KeyHints` Vimperium; `ResultRow`, бейджи Runwa). Клавиши Vim (h / l в формах) в пакет не входят: для них у `Select` есть `handle`, остальные компоненты принимают `data-*` атрибуты.
- **Выпуск для приложений:** поднять `version` в `packages/ui/package.json`, закоммитить, затем `npm run ui:release -- --push`. Команда собирает пакет и кладёт собранное (`package.json` + `dist/`) коммитом в ветку `ui-dist` с тегом `ui-v<версия>`; затем создаёт на GitHub выпуск с архивом `bedware-ui-<версия>.tgz`; рабочую папку не трогает. Ветку `ui-dist` руками не править.
- Приложения подключают архив выпуска: `npm install https://github.com/bedware-software/bedware-design/releases/download/ui-v<версия>/bedware-ui-<версия>.tgz`. Git-зависимость (`github:…#тег`) не годится: npm записывает её в `package-lock.json` как `git+ssh`, и сборка приложений на GitHub её не скачивает. Обновление в приложении — та же команда с новой версией.
- Варианты для выбора владельцем показывать на странице `ui.html` отдельным разделом (классы `alt-*` в её `<style>`, разметка в `demo/showcase.tsx`); в пакет они не попадают и после решения убираются.

## Дизайн-система в Claude

- Адрес: https://claude.ai/artifact/7ziWJQRMsKAjfqwL6aPdQ2 — тип Design System, название «bedware», приватная.
- Публикация — инструментом Artifact: `url` = адрес выше, `root` = `<репозиторий>/design-system`, `file_path` = один изменённый файл по полному пути, `files` = остальные изменённые (`project/...` → `project/...`). Отправлять только изменённые файлы.
- Индекс `project/design-system.json` отправлять только когда изменились его собственные поля (название, запись о картинке), последним, с обновлённым `lastChange`.
- Картинки (логотипы, робот) — это загрузки (`asset: true`), их id записаны в индексе. При замене картинки: загрузить новую, вписать её id в индекс, старую удалить.
- Хранилище вырезает из SVG вшитые растровые картинки — постеры с подложкой загружать как PNG.
- Формат токенов дизайн-системы не принимает семейство `motion` — сборщик его убирает.
- Превью компонентов — образцы пакета (`packages/ui/demo/stories.tsx`), отрисованные в статичный HTML; высота карточки задаётся там же, полем `height`.
- Команда `/design-sync` пока не используется: публикация идёт сборщиком `npm run design-system`. Пакет `@bedware/ui` теперь есть — к `/design-sync` можно вернуться, если понадобятся живые React-компоненты в самой дизайн-системе.

## Страницы

- `ui.html` — витрина пакета `@bedware/ui`: каждый компонент во всех состояниях, переключатель темы. Основная страница для проверки компонентов.
- `system.html` — чистовой итог бренда: логотип, шесть первых компонентов, токены.
- `light.html` — три варианта светлой темы (история выбора; выбран B).
- `index.html` — этап 1: палитра, шрифты, каталог Runwa и Vimperium «рядом», таблица расхождений (история выбора).
- `c.html` — доводка направления C (история выбора).
- `vimperium.html` — миграция Vimperium на токены: варианты по тому, чего нет в дизайн-системе (ступени яркости тем, поле, цвета групп вкладок, кромка режима Vim). Всё решено, см. `DECISIONS.md` (история выбора).
- `catalog/` — настоящий CSS приложений для каталога; пересборка `npm run catalog:css` (читает приложения, ничего в них не пишет).
